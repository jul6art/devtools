# Writing the knowledge of a stack — prompt knowledge/1

DevTools documents projects in any language. Before a page of a stack can be written — or its entry
points found — it needs a **knowledge file**: how that framework works, independently of any project.

## What you receive

The brief (`.devtools/pending/knowledge.<key>.brief.xml`) names the stack (`<stack language framework
version>`), the canvas to follow (`<canvas path>`) and where to write (`<draft path>`).

## What you do

1. **Consult the official documentation of that framework and version** — search the web; do not write
   from memory what you can check.
2. Write the draft following the canvas **exactly**: the title `# <Stack> <major>`, then the seven sections
   in their order. Every section is filled; "Pièges connus" says what actually surprises developers.
3. "Sources" lists the URLs you consulted, one per line. A draft without sources is refused.

## What makes it useful

- Name the classes, events and attributes a reader meets in code.
- Say where each type of entry point is declared, and which command lists them if one exists.
- Stay generic: nothing about the project at hand belongs here — the same file serves every project on this
  stack.
